Chapter 3

Project Intent & Target Audience

Before any code, what are we building, and for whom?

3.1 What DClaw Marketing is

DClaw Marketing is an agent-driven marketing operating system — a single multi-tenant platform that lets a marketing team (internal department or external agency) hand a brief to a fleet of specialised LLM agents and have it travel, gated, all the way to published content, attributable revenue, and a client-ready report.

The platform combines four ideas that are usually sold separately:

1 · Agent fleet

A Conductor + role specialists (Social Media Manager, SEO Specialist, Paid Media Specialist, Creatives, Analyst, plus Reviewer/Viewer/Client roles). Each agent owns a "station" in the product.

2 · Hard-gate supervision

Every outbound action — a tweet, an ad spend, an email send — files an Approval Request first. A human reviewer can approve, reject with reason, or let it auto-expire. Nothing escapes the gate.

3 · Bring-your-own everything via MCP

A registry of 35 MCP servers (HubSpot, Ahrefs, GA4, Mailchimp, Stripe, …). Agents call tools through a unified async client; secrets are Fernet-encrypted per-org.

4 · Closed analytics loop

Touchpoints + Conversions are linked via identity resolution; daily rollups feed multi-model attribution; dashboards close the "did the agent move revenue?" question.

3.3 Differentiators

  • Hard-gate by default — agents never publish on their own; everything funnels through Approval. PLAN-v1.2 §v2.0 §5.2 codifies this.
  • Multi-tenant from line one — every row has organization_id; every API call is scoped by membership. No "later we'll add tenancy."
  • Agent fleet, not a single chatbot — each role has its own system prompt, its own station, its own thread. The Conductor decomposes briefs and routes work.
  • Brand-aware — the active BrandKit (palette, fonts, voice sliders) is prepended to every creative prompt, copy or visual.
  • Provider-or-stub everything — no real API key? You still get a deterministic stub response so dev/CI keeps working. Replicate, ElevenLabs, Resend, Anthropic, MCP, Bluesky/LinkedIn/X/Instagram, all follow the same pattern.
  • Open data model — Touchpoint, Conversion, CostLedger, AttributionResult, AnalyticsRollup are first-class tables. Not a closed black box.

5.2 Cross-cutting requirements

These constraints apply to every phase and are non-negotiable per PLAN-v1.2:

Hard-gate by default

Outbound posting, ads spend, email broadcasts — all funnel through ApprovalRequest. Per PLAN-v1.2 §v2.0 §5.2. Auto-approval is opt-in per action class via Organization.autonomy_posture_json.

Multi-tenant from line one

Every domain row has organization_id. Every API endpoint enforces membership. Every secret is scoped to one Org.

Light-mode only

No dark: Tailwind variants. The platform is single-mode by design. Reduces visual debt during v1.2 race.

Provider-or-stub

No real API key? Get a deterministic stub. Replicate, ElevenLabs, Resend, MCP, Anthropic, all four publishers — same pattern. Dev never blocked on credentials.

Audited everything

Every approve/reject/cancel writes an AuditEvent with actor, target, IP, and reason. Foundation for SOC-2.

Encrypted secret store

All third-party access tokens encrypted at rest with cryptography.fernet keyed off a per-Org master key. Live behind app.services.secret_box.
