Top three takeaways

1. Real agents now run the platform.

Until v1.1.1, every "agent" was a thin wrapper around a single inline LLM call. After v1.1.2 the Conductor decomposes a brief into tasks, dispatches each to one of seven role-agents (Strategist, Creative Director, Copywriter, Editor, SEO Analyst, Distributor, Reporter), routes through the resolver chain, writes a ModelCallLog row per call, and lands the output in the Approval Inbox with the original reasoning trace replayable on demand.

2. The model layer is operator-owned.

The 26-provider Model Registry means every operator picks their own LLM stack (OpenAI / Anthropic / Google / OpenRouter / Together / Groq / Mistral / xAI / Replicate / RunPod / Ollama / vLLM / LM Studio + the multimedia + speech specialists), watches health-checks tick over every five minutes, and pins defaults at org level with per-user overrides on top.

3. Workflows ship with five working templates.

launch_announcement / weekly_digest / lead_magnet / ad_campaign / aeo_audit all run end-to-end through the sandbox harness. An operator clones a template into their org from /workflows/templates and is producing approved output in one round-trip.

+ Sprint 5 opens with: real-time streaming, LLM-judged AEO, native Vertex/Bedrock probes.

Sprint 4 made the agent flow real. Sprint 5 should make it feel real — token-by-token output in the Conductor, second-pass LLM scoring on every AEO run, and proper provider parity for the two cloud-native LLM stacks that today fall back to unknown.

Chapter 3

Project Intent & Target Audience

3.1 What DClaw Marketing is

DClaw Marketing is an agent-driven marketing operating system. A small team — or one operator plus AI agents — runs a full marketing function. Humans set the brand kit and feed in source material; AI agents draft content, schedule posts, run ads, surface analytics, and propose actions. Humans supervise from their Station and approve outbound actions in an Approval Inbox. Agents never publish without consent.

The system is multi-tenant by design (Organization → Project → Asset hierarchy), brand-aware (versioned BrandKit injected into every prompt), knowledge-grounded (ingestion → embeddings → KG with write-back insights), and audit-traced end-to-end. Every cost is metered; every action is logged. As of Sprint 4, every model call is logged too — through the Model Registry's ModelCallLog table the operator can stream live.

3.2 The people we're building for

The Solo Operator

A founder, consultant, or in-house marketer running marketing for a single business. Needs the full stack but can't justify a 5-person team. DClaw acts as their force multiplier.

The Boutique Agency

2–10 people serving multiple clients. Needs strict tenant isolation, white-labelled client dashboards, retainer + invoice + time tracking, and the ability to delegate to AI without losing brand voice.

The In-House Marketing Function

A growing company's marketing team. Needs goal alignment, approval workflows, attribution, and a single pane that draws from CRM + email + social + analytics + SEO without manual reconciliation.

3.3 Differentiators (post-Sprint 4)

  • Approval-first. Every outbound action ends in an Approval Inbox before going out. 4-eye threshold (approvers_required) shipped in Sprint 4 means operators can demand N-of-M sign-off on high-impact actions.
  • Brand-conditioned generation. The BrandKit and the KG write-back insights are injected into every prompt — agents inherit the brand voice automatically. Sprint 4's dont_say lint refuses banned phrases at the gateway.
  • BYO model layer. Sprint 4 made every LLM call go through the resolver. The operator brings their own provider keys — OpenAI / Anthropic / Google / OpenRouter / Together / Groq / xAI / Mistral / Replicate / RunPod / Ollama / vLLM / LM Studio and the multimedia + speech specialists are all first-class.
  • MCP-first integrations. 14 concrete adapters + BYO MCP marketplace; six new generation-adapter shells shipped in Sprint 4 (Replicate / Runway / Suno / ElevenLabs / Cartesia / Deepgram).
  • Self-hosted by default. Docker Compose stack; the operator owns the Fernet master key and can swap LLM providers at any time.
  • Auditable. Every admin action, agent run, model call, and outbound publish is recorded in audit_events + model_call_logs with the actor, the target, and the payload. Sprint 4's retention pruner keeps the table from growing unbounded.

After Sprint 4 we are materially in that posture: every backend the demo needs exists; the agent layer is now real, not stubbed; the operator can drive the platform end-to-end through a single chat box. The remaining Sprint 5 work is polish (real-time streaming, LLM-judged AEO, native cloud-LLM probes) and presentation (marketing collaterals) rather than core platform.
